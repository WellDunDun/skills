# Product Surface

Use this reference to set the visual and interaction direction before touching widgets.

## Classify the surface

- Productivity, operations, CRM, admin, finance, health records: prioritize scanning, density, predictable navigation, quiet color, stable tables/lists, filters, and error recovery.
- Consumer browsing, travel, media, food, shopping: prioritize images, browsing momentum, clear primary actions, save/share states, and confident purchase or booking flows.
- Creation tools, editors, design apps, developer tools: prioritize canvas/work area, keyboard access, command surfaces, inspectors, panels, undo/redo, and direct manipulation.
- Education, onboarding, coaching: prioritize pace, comprehension, progress, friendly empty states, and low cognitive load.
- Games, immersive media, highly branded campaigns: use expressive motion, full-bleed visuals, and custom drawing only when it serves the core experience.

## Density decisions

- Compact operational UI: smaller headings, tighter vertical rhythm, persistent filters, list density controls, and visible status.
- Editorial UI: larger type, media-led hierarchy, breathable sections, and fewer simultaneous controls.
- Tool UI: fixed toolbars, icon buttons with tooltips, split panes, shortcut-aware commands, and stable canvas dimensions.
- Commerce UI: product media first, persistent price/action context, clear variant selection, inventory/error states, and trust cues near the action.

## First screen requirements

- The first viewport should be the actual app experience, not a marketing explanation.
- Show the primary object of work immediately: inbox, map, editor, feed, board, catalog, player, dashboard, or form.
- If the app is branded, make the brand, product, venue, object, or domain visible through content and styling, not only an app bar title.
- Leave a clear path to the next section or next state; avoid dead first screens with only a logo and button.

## Visual direction prompts

- What does the user need to decide in the first 10 seconds?
- What needs to be scanned repeatedly?
- What is the most expensive mistake the UI can allow?
- Which data or object deserves the largest area?
- Which states are frequent enough to design carefully?

## Anti-patterns

- Generic dashboard made of identical cards with no hierarchy.
- Oversized hero treatment inside a work app where users need lists, filters, and actions.
- Decorative gradients replacing actual product imagery or data.
- Split text/media marketing composition when the user asked for an app or tool.
- Empty state copy that explains the feature instead of offering the next useful action.
