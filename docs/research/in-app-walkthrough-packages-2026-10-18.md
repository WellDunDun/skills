# Contextual in-app walkthrough packages

Checked 2026-10-18 against official documentation, GitHub repositories and public npm/GitHub APIs. This is research only. No package was installed or integrated.

Yes, popular packages already handle anchored tooltips, spotlights, step navigation and interaction hooks. Start with **Driver.js** for a framework-neutral implementation or **React Joyride** for a React application. Build the product's task definitions and completion checks around the library.

## Practical comparison

| Package | Action and asynchronous steps | Fit and limitation |
| --- | --- | --- |
| Driver.js | `advanceOnClick`, `waitForElement`, and `onNextClick` plus manual `moveNext()` support delayed UI and user interaction. | Best initial default when the framework is unspecified. A click can advance a tour, but the app must establish whether a task actually succeeded. [Interactive tours](https://driverjs.com/docs/interactive-tours) |
| React Joyride | `before` / `after` hooks, target waiting, `onEvent`, controls and externally controlled `stepIndex`. | Strong React fit. npm declares React and React DOM 16.8 through 19 peers. Prefer lifecycle hooks for opening UI; use controlled mode when the app truly owns navigation. [Recipes](https://react-joyride.com/docs/recipes), [hook](https://react-joyride.com/docs/hook), [package metadata](https://registry.npmjs.org/react-joyride) |
| Shepherd | `beforeShowPromise`, event-based `advanceOn`, custom button actions, named steps, `showOn`, target waiting and missing-target skipping. | Strong event-driven option. Its commercial licensing terms make it a less convenient default for proprietary products. [Usage](https://docs.shepherdjs.dev/guides/usage/) |
| Reactour | Provider and `useTour` state, per-step `action` / `actionAfter`, custom controls and selector observers. | Reasonable if already used. The inspected docs type actions as returning `void`; do not assume they provide Shepherd-style awaited promises. Recent HEAD tests do not establish what shipped in 3.8.0. [Props](https://docs.reactour.dev/tour/props), [hooks](https://docs.reactour.dev/tour/hooks) |
| Intro.js | Callback hooks can return promises, which the library awaits before proceeding. | Established vanilla alternative, with a commercial-license decision for proprietary use. [Async callbacks](https://introjs.com/docs/tour/examples/async-await), [license](https://introjs.com/docs/getting-started/license) |

The MIT licenses permit commercial use while requiring preservation of the copyright and permission notices. See the release-tagged [Driver.js license](https://github.com/nilbuild/driver.js/blob/1.10.1/packages/driver/license), [Joyride license](https://github.com/gilbarbara/react-joyride/blob/v3.2.0/LICENSE) and [Reactour license](https://github.com/elrumordelaluz/reactour/blob/main/LICENSE). Shepherd's release-tagged license expressly says a commercial license is required for revenue-generating companies, including internal tools. Intro.js publishes AGPLv3 and commercial terms. These are the maintainers' stated conditions, not an independent legal interpretation. [Shepherd license](https://github.com/shipshapecode/shepherd/blob/v7.0.6-react-shepherd/LICENSE.md), [Intro.js license](https://github.com/usablica/intro.js/blob/v8.6.0/license.md).

## Accessibility evidence and remaining product work

Joyride documents ARIA dialog semantics, focus trapping and focus restoration. Its v3.2.0 source tests assert Tab cycling, Shift+Tab and restoration. Driver.js 1.10.1 tests assert keyboard navigation, close behavior and labelled dialog attributes. Shepherd's matching release includes browser tests for focus trapping, the attached target, keyboard actions and accessible names. I inspected these assertions; I did not execute the suites or test a screen reader. [Joyride documentation](https://react-joyride.com/docs/accessibility), [Joyride focus tests](https://github.com/gilbarbara/react-joyride/blob/v3.2.0/test/hooks/useFocusTrap.spec.tsx), [Driver keyboard tests](https://github.com/nilbuild/driver.js/blob/1.10.1/packages/driver/tests/keyboard.test.ts), [Driver dialog tests](https://github.com/nilbuild/driver.js/blob/1.10.1/packages/driver/tests/popover.test.ts), [Shepherd accessibility tests](https://github.com/shipshapecode/shepherd/blob/v7.0.6-react-shepherd/shepherd.js/test/cypress/integration/a11y.cy.js).

For a walkthrough that requires typing into the real application, test the whole task with the keyboard. Joyride's default focus trap confines Tab navigation to the tooltip; its docs describe disabling that trap for modal form inputs. Reactour also exposes `disableFocusLock`. Neither option alone proves an accessible end-to-end task. [Joyride recipes](https://react-joyride.com/docs/recipes), [Reactour props](https://docs.reactour.dev/tour/props).

Cross-route orchestration remains app work. Keep the tour controller above route components, use stable step IDs, navigate explicitly, wait for the destination target and persist progress if reload/resume is required. Driver's docs explicitly demonstrate storing progress and resuming after navigation; Joyride exposes controlled state; Shepherd exposes named-step navigation. These capabilities are building blocks, not verified automatic integration with every router. [Driver interactive tours](https://driverjs.com/docs/interactive-tours), [Joyride controls](https://react-joyride.com/docs/hook), [Shepherd methods](https://docs.shepherdjs.dev/guides/usage/).

For contextual learning, the app still needs to select relevant tasks, express prerequisites, wait for successful domain actions, track completion and choose when to offer help. The recommended next evaluation is one real multi-step task with an asynchronous result, one route change, keyboard operation, cancellation and resume. No application stack, installed versions, bundle sizes, mobile behavior or end-user accessibility outcomes were verified here.
